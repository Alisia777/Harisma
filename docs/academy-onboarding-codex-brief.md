# Qharisma Academy / Onboarding — Codex implementation brief

Дата: 2026-07-09  
Статус: дизайн-спецификация для Codex  
Цель: добавить в портал красивое обучение сотрудников по каждой вкладке, первый вход, тестирование и контекстные подсказки без поломки текущих рабочих экранов.

---

## 0. Что именно нужно реализовать

Нужно превратить портал в систему, где сотрудник не просто видит вкладки, а понимает:

- где что смотреть;
- что означает каждая вкладка;
- когда обновляются данные;
- как заводить новинку;
- как менять статус;
- как работать с репрайсером;
- как проверять цены;
- где смотреть воронку;
- где смотреть / вести контент-завод;
- где заводить задачи и изменения;
- как пройти тест и подтвердить, что сотрудник понял базовую механику портала.

Это должно быть сделано в стиле текущего портала: тёмная премиальная оболочка, стеклянные карточки, золотые/синие/изумрудные акценты, мягкая динамика, аккуратные hover-состояния, без визуального конфликта с существующими классами.

## 1. Интеграция в текущий портал

Портал сейчас работает как статический GitHub Pages / single-page shell:

- `index.html` содержит боковое меню `.nav-btn[data-view]`;
- каждая вкладка — это `<section class="view" id="view-...">`;
- основные скрипты подключаются через `type="application/x-altea-auth-delayed"`;
- стили уже используют CSS variables: `--bg`, `--panel`, `--text`, `--muted`, `--line`, `--ok`, `--warn`, `--danger`, `--info`, `--radius`;
- в проекте уже есть визуальные form-классы `.ui-group`, `.ui-field`, `.ui-grid-2`, `.ui-grid-3`, `.ui-note`, `.ui-actions`.

### Добавить в `index.html`

В блок CSS рядом с остальными стилями:

```html
<link rel="stylesheet" href="portal-academy-onboarding.css?v=20260709academy1">
```

В боковое меню после «Дашборд» или перед «Хранилище»:

```html
<button class="nav-btn" data-view="academy">
  <span>Академия</span>
  <small>обучение · тесты · подсказки</small>
</button>
```

В список view-секций:

```html
<section class="view" id="view-academy"></section>
```

В конец списка auth-delayed скриптов:

```html
<script type="application/x-altea-auth-delayed" data-auth-src="portal-academy-onboarding.js?v=20260709academy1"></script>
```

Не менять архитектуру роутинга. Если в проекте уже есть `setView(view)` / `rerenderCurrentView()`, использовать их. Если нет — в модуле сделать безопасный fallback для переключения `.view.active` и `.nav-btn.active`.

### Обязательные ограничения

- Не добавлять внешних зависимостей.
- Не ломать существующие вкладки.
- Все новые CSS-классы должны начинаться с `.academy-`.
- Все новые storage keys должны начинаться с `altea:academy:v1:`.
- JS должен быть обёрнут в IIFE с guard:

```js
(function () {
  if (window.__ALTEA_ACADEMY_ONBOARDING_V1__) return;
  window.__ALTEA_ACADEMY_ONBOARDING_V1__ = true;
  // ...
})();
```

- Все пользовательские строки в HTML должны проходить через `escapeHtmlSafe()`.
- Учесть `prefers-reduced-motion`.
- Не использовать `alert()` для обычного UX.

## 3. Главная UX-идея

Добавить три слоя обучения.

### 3.1. Первый вход

При первом входе сотрудника в портал показать красивый onboarding-gate:

1. приветствие;
2. роль сотрудника;
3. что такое портал;
4. когда обновляются данные — обязательно указать `ежедневно в 11:00 по Москве`;
5. как задавать вопросы / что делать, если данные странные;
6. базовый тест;
7. экран результата.

Если сотрудник прошёл базовый тест на 80%+, в localStorage ставится отметка.

Ключ:

```js
'altea:academy:v1:firstGatePassed'
```

Важно: на первом MVP не блокировать полностью работу портала навсегда. Сделать режим: overlay закрывается после прохождения или кнопкой «Пройти позже», но в topbar остаётся заметный бейдж «Обучение не пройдено».

### 3.2. Вкладка «Академия»

Новая полноценная вкладка, где видны:

- прогресс сотрудника;
- обязательные модули;
- модули по ролям;
- последние изменения в портале;
- мини-тесты;
- «продолжить обучение»;
- сертификат / статус прохождения.

### 3.3. Контекстная помощь на каждой вкладке

На ключевых вкладках добавить маленькую кнопку:

```text
? Как пользоваться этим разделом
```

При клике открывается правый drawer с обучением именно по текущей вкладке:

- что это за вкладка;
- какие данные здесь есть;
- источник данных;
- когда обновляется;
- что можно делать;
- чего нельзя делать;
- типовой сценарий;
- частые ошибки;
- мини-тест.

## 4. Визуальный стиль

### 4.1. Цветовая логика

Использовать текущие переменные портала, но добавить локальные academy-токены:

```css
:root {
  --academy-gold: #d4a44a;
  --academy-gold-2: #f5ddb0;
  --academy-blue: #3b82f6;
  --academy-violet: #8b5cf6;
  --academy-emerald: #5fb084;
  --academy-coral: #e5695f;
  --academy-glass: rgba(255,255,255,.045);
  --academy-glass-strong: rgba(255,255,255,.08);
  --academy-shadow: 0 18px 44px rgba(0,0,0,.26);
}
```

Тоны модулей:

| Модуль | Акцент |
|---|---|
| База портала | blue |
| Новинки | gold |
| Статусы | violet |
| Репрайсер | emerald |
| Проверка цен | amber/gold |
| Воронка | blue/violet |
| Контент-завод | coral/gold |
| Реестр / Tracker | emerald/blue |
| Данные / обновление 11:00 | blue |

### 4.2. Динамика

Добавить мягкую премиальную динамику:

- появление карточек через `transform: translateY(8px); opacity: 0 -> 1`;
- hover карточек: `translateY(-2px)`, подсветка border;
- progress ring / progress bar с плавным заполнением;
- shimmer только на skeleton/loading;
- pulse-dot около статуса «данные обновляются в 11:00 по Москве»;
- тестовые ответы подсвечиваются `ok/warn/danger`;
- drawer открывается справа через `transform: translateX(100%) -> 0`;
- для reduced motion все анимации отключить.

Пример:

```css
.academy-card {
  animation: academyRise .32s ease both;
}
@keyframes academyRise {
  from { opacity: 0; transform: translateY(8px); }
  to { opacity: 1; transform: translateY(0); }
}
@media (prefers-reduced-motion: reduce) {
  .academy-card, .academy-drawer, .academy-progress-fill { animation: none !important; transition: none !important; }
}
```

## 6. Обязательные модули обучения

### 6.1. База портала

Цель: сотрудник понимает, что портал — единая точка входа.

Покрыть:

- боковое меню;
- topbar;
- статус синхронизации;
- фильтры;
- дата последнего обновления;
- правило `11:00 по Москве`;
- что делать, если данные странные;
- где искать инструкции.

Мини-тест:

- во сколько обновляются данные;
- что делать до 11:00;
- куда смотреть при расхождении;
- когда создавать задачу.

### 6.2. Новинки

Цель: сотрудник может завести новинку и понять её путь.

Связанные view:

- `launches` — продукты / новинки;
- `launch-control` — запуск новинок, если вкладка доступна;
- `sku-contour` — связь с SKU workspace.

Покрыть:

- как найти вкладку «Продукты / Новинки»;
- как завести новинку;
- какие поля обязательны;
- owner;
- маркетплейс;
- плановая дата запуска;
- статус;
- фаза;
- чек-лист;
- блокер;
- next step;
- когда считается «готово к запуску»;
- когда нельзя переводить статус дальше.

Практический сценарий:

```text
Открыть Продукты / Новинки → выбрать/создать карточку → заполнить SKU, название, owner, MP, план запуска → указать статус Подготовка → создать чек-лист → назначить задачи → сохранить.
```

Мини-тест:

- какой статус ставится при начале подготовки;
- можно ли ставить «Готово», если нет цены / контента / рекламы;
- что обязательно писать при блокере.

### 6.3. Статусы

Цель: сотрудник понимает, что статус — это не настроение, а управленческий сигнал.

Связанные view:

- `control`;
- `launches`;
- `launch-control`;
- `sku-contour`.

Покрыть:

- кто может менять статус;
- обязательный комментарий при изменении;
- статус «Проблема» требует блокер + next step;
- финальные статусы нельзя ставить без критерия завершения;
- различие задачи, процесса, гипотезы и проекта.

### 6.4. Репрайсер

Цель: сотрудник понимает, как читать рекомендации репрайсера и не загрузить опасную цену.

Связанный view: `repricer`.

Покрыть:

- что такое репрайсер;
- где текущая цена;
- где рекомендованная цена;
- где min price / price floor;
- где риск;
- что значит `ok/warn/danger`;
- что делать, если цена ниже минимума;
- как проверить файл перед загрузкой;
- что делать после загрузки;
- как откатить или эскалировать.

Практический сценарий:

```text
Открыть Репрайсер → выбрать MP/SKU → проверить текущую цену → сравнить с min price → посмотреть риск → скачать/подготовить файл → проверить перед загрузкой → зафиксировать действие.
```

Мини-тест:

- что делать, если рекомендация ниже минимальной цены;
- можно ли применять цену без проверки маржи;
- где смотреть статус риска.

### 6.5. Проверка цен

Цель: сотрудник может понять, почему цена в портале отличается от маркетплейса.

Связанные view:

- `prices`;
- `repricer`;
- `product-leaderboard`;
- `iu-drr`.

Покрыть:

- актуальная цена;
- цена со скидкой;
- СПП / промо;
- маржа;
- дата обновления;
- сверка WB / Ozon / Я.Маркет;
- что делать при расхождении.

Правило:

```text
Перед эскалацией проверить: время обновления → источник цены → была ли загрузка репрайсера → есть ли промо/скидка → только потом создавать задачу.
```

### 6.6. Воронка

Цель: сотрудник понимает, где искать причину падения заказов.

Связанные view:

- `product-leaderboard` — КЗ / воронка / ROMI;
- `iu-drr` — показатели площадок;
- `dashboard` — общий сигнал.

Покрыть:

- показы;
- клики;
- CTR;
- корзина;
- заказ;
- выкуп;
- возвраты;
- ROMI;
- как понять, где провал;
- связь цены, карточки, остатков и рекламы.

Практический сценарий:

```text
Заказы упали → открыть Воронку → найти этап провала → проверить цену → проверить остатки → проверить карточку/контент → проверить рекламу → создать задачу с причиной.
```

### 6.7. Контент-завод

Цель: сотрудник понимает, где смотреть задачи и статусы контента.

Связанные view:

- если есть отдельная вкладка `content-factory`, использовать её;
- если её нет, модуль показывается в Академии и может вести в `documents` / `control` / будущую вкладку.

Покрыть:

- где ТЗ;
- где статусы контента;
- кто owner;
- где дедлайн;
- где проверить результат;
- что делать, если контент не по ТЗ;
- что нельзя грузить постфактум без проверки;
- связь контента с карточкой и запуском новинки.

### 6.8. Реестр изменений / Tracker / Задачи

Цель: сотрудник понимает, где обычная задача, где изменение, где процесс, где проект.

Связанный view: `control`.

Покрыть:

- как создать задачу;
- как описать результат;
- что такое критерий завершения;
- как проставить owner;
- как поставить срок;
- как менять статус;
- когда эскалировать смежный отдел.

### 8.2. Safe routing helper

```js
function openPortalView(viewId) {
  if (!viewId) return;
  if (typeof window.setView === 'function') {
    window.setView(viewId);
    return;
  }
  document.querySelectorAll('.view').forEach((section) => {
    section.classList.toggle('active', section.id === `view-${viewId}`);
  });
  document.querySelectorAll('.nav-btn[data-view]').forEach((button) => {
    button.classList.toggle('active', button.dataset.view === viewId);
  });
}
```

## 9. Контент тестов

Проходной балл: `80%`.

Вопросы должны быть практическими, не теоретическими.

Пример по базовому модулю:

```js
{
  question: 'Сейчас 10:35 по Москве, показатели выглядят странно. Что делаем сначала?',
  options: [
    'Сразу пишем в общий чат, что всё сломалось',
    'Проверяем дату последнего обновления и ждём 11:00 МСК',
    'Меняем цену вручную',
    'Удаляем фильтры и считаем вручную'
  ],
  answer: 1,
  explain: 'До ежедневного обновления часть данных может быть неполной.'
}
```

Пример по репрайсеру:

```js
{
  question: 'Репрайсер предлагает цену ниже минимальной. Что делать?',
  options: [
    'Загрузить, если хочется поднять продажи',
    'Не загружать, проверить правило и эскалировать ответственному',
    'Поставить любую цену конкурента',
    'Скрыть товар'
  ],
  answer: 1,
  explain: 'Цена ниже минимума — риск маржи/экономики, нужна проверка.'
}
```

### 10.2. In progress

- золотая подсветка;
- CTA: «Продолжить»;
- показывать последний урок.

### 10.3. Test failed

- мягкий warn/danger, не токсично;
- показать неправильные ответы;
- CTA: «Повторить тест»;
- не сбрасывать просмотренные уроки.

### 10.4. Passed

- изумрудный статус;
- бейдж «Пройдено»;
- дата прохождения;
- возможность открыть повторно.

## 11. Адаптивность

Desktop:

- Academy hub: hero + 3 колонки карточек;
- module player: sidebar уроков + main + right checklist;
- drawer справа 420–480 px.

Tablet:

- 2 колонки карточек;
- module player: уроки сверху, контент ниже.

Mobile:

- 1 колонка;
- drawer full-screen;
- тестовые варианты крупными кнопками;
- без мелких hover-only подсказок.

---

## 12. Доступность

- Все кнопки с `type="button"`.
- Drawer: `role="dialog"`, `aria-modal="true"`, close by Escape.
- Progress ring иметь текстовую подпись.
- Не передавать смысл только цветом.
- Focus styles не убирать.
- Контраст текста не ниже текущего уровня портала.

## 13. Acceptance criteria

Codex должен считать задачу готовой, если:

1. В боковом меню появилась вкладка «Академия».
2. `#view-academy` рендерится без ошибок.
3. При первом входе появляется onboarding-gate.
4. В gate есть правило `данные обновляются в 11:00 по Москве`.
5. Есть модули: База, Новинки, Статусы, Репрайсер, Цены, Воронка, Контент-завод, Реестр/Tracker.
6. У каждого модуля есть уроки и тест.
7. Тест считает score и pass/fail.
8. Progress сохраняется в localStorage.
9. На ключевых вкладках появляется кнопка «Как пользоваться разделом».
10. Drawer показывает контекстную инструкцию по текущей вкладке.
11. Все классы изолированы `.academy-*`.
12. Нет внешних зависимостей.
13. Нет console errors при переключении вкладок.
14. Существующие вкладки `dashboard`, `launches`, `repricer`, `prices`, `product-leaderboard`, `control` не ломаются.
15. Работает на mobile.
16. Учитывается `prefers-reduced-motion`.
