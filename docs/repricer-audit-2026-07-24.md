# Аудит репрайсера — 24.07.2026

## Итог

Репрайсер переведён на безопасную схему перехода: интерфейс уже показывает канонический расчёт в режиме аудита, но ни одна цена не может попасть в рабочую выгрузку без автоматического cutover-gate.

Приоритет цены для активного, нового и повторно запускаемого товара:

1. обязательная маржа;
2. MIN;
3. MAX;
4. остальные ограничения и сигналы репрайсера.

Если цена, обеспечивающая маржу, выше MAX, effective MAX поднимается до margin floor. Снижение ниже margin floor запрещено. Отсутствующая маржа не заменяется скрытым процентом: строка блокируется до загрузки утверждённого значения.

## Что упрощено

- Один серверный реестр `repricer_minmax_registry.json` хранит утверждённые маржу, MIN и MAX по SKU и площадке.
- Одна серверная политика `repricer_economics_policy.json` хранит комиссию, расходы площадки без рекламы, внутреннюю рекламу и налоговую ставку WB/Ozon; браузерные значения больше не являются единственным источником расчёта.
- Один отчёт `repricer_margin_minmax_gaps.json` даёт готовую очередь строк, которые нельзя выпускать без заполнения.
- Один `repricer_live_signals.json` хранит согласованный срез внутренней рекламы, прямых/резервных остатков и OOS.
- Один `repricer_live_prices.json` хранит серверный снимок цен WB/Ozon, сопоставленный с `articleKey`; браузер не получает ключи площадок.
- Один `repricer_team_policy_proposals.json` хранит готовый пакет маржа/MIN/MAX для команды со статусом РОП и запретом автоприменения.
- Командный Excel содержит первую колонку `Маржа, %`, формульные `minPrice`/`maxPrice`, отдельные листы статусов/OOS, проверок и источников.
- Один `repricer_shadow_report.json` показывает расхождения canonical/legacy и автоматически решает, разрешено ли переключение.
- Интерфейс показывает явный режим `CANONICAL AUDIT` или `CANONICAL ACTIVE`, количество стопов маржа/MIN/MAX и паритет цен. Legacy-рекомендации больше не подменяют канонический аудит при заблокированном cutover.
- Загрузчик принимает XLSX, XLS, CSV и TSV на сервере. Браузерный аудит проверен для XLS, CSV и TSV; настоящий XLSX направляется через серверный загрузчик.
- Неизменённый аудит теперь даёт `0` операций: расчётная колонка `Маржа, %` больше не принимается за входную. Изменение маржи читается только из явной колонки `Новая маржа SKU, %`.
- Загрузчик истории ИУ принимает новый 8-колоночный формат с `master_id`. Файл «продажи бигл 23.07» разобран: 22 дня, 496,44 млн ₽ продаж, 48,33 млн ₽ рекламы и 8% рекламного плана. История сохранена отдельно для `master_id=433608`, без смешения с другим кабинетом.
- Экспорт аудита содержит отдельные поля новой маржи, MIN, MAX, себестоимости, статуса и комментария. Неизменённый экспорт можно загрузить обратно без ложных операций.
- SKU Workspace теперь показывает план-факт, маржу, остаток и оборачиваемость в одной строке и в карточке решения. Выбор нового статуса не меняет товар: он создаёт автозадачу со статусом `waiting_rop`.
- Подтверждение РОПа применяет статус и закрывает задачу. Возврат РОПом оставляет исходный статус и переводит решение на доработку.
- Для автоматической, ручной и импортированной цены действует один шлюз: изменение на 10% и более создаёт дедуплицированную задачу и не попадает в рабочий override или выгрузку до подтверждения РОПа.
- Цена старше 2 дней или без надёжной даты получает красный стоп. Жёлтый confidence больше не разрешает обойти freshness-gate.
- Canonical и legacy сначала используют подтверждённый lifecycle/статус SKU. Прямое изменение статуса из профиля репрайсера и файла аудита закрыто.
- Подтверждённые lifecycle-решения могут поступать в canonical через серверный `product_lifecycle_approved.json`; черновики и `waiting_rop` игнорируются.
- Согласованные цена и статус сохраняются в общем серверном `repricer_controls`, затем материализуются в `repricer_approved_overrides.json` и `product_lifecycle_approved.json` перед каждой canonical-сборкой. Согласованная цена повторно зажимается маржой/MIN/MAX и не может обойти экономический floor.
- Статус больше нельзя менять параллельно во вкладках «Цены» и «Репрайсер»: оттуда пользователь переходит в единый SKU Workspace.

## Упрощённый рабочий процесс

1. Менеджер открывает SKU Workspace и видит в одной строке статус, owner, план-факт, маржу, остаток и действующую задачу.
2. При необходимости менеджер предлагает новый статус и фиксирует основание по цифрам.
3. Портал автоматически создаёт одну задачу РОПу; товар до решения не меняется.
4. РОП подтверждает и система применяет статус либо возвращает решение на доработку.
5. Репрайсер сначала защищает маржу активного/нового/перезапускаемого товара, затем MIN/MAX. Для вывода маржинальный запрет не применяется, но смена статуса всё равно требует подтверждения.
6. Любая резкая цена — автоматическая, ручная или из файла — проходит шаг РОПа. Повторный расчёт той же цены не создаёт дубль задачи.

## Cutover-gate

Canonical может заменить legacy только одновременно при выполнении условий:

- незаполненных обязательных маржа/MIN/MAX — 0;
- готовность canonical — не менее 95%;
- совпадение готовых цен с legacy в пределах 1 ₽ — не менее 95%;
- статус canonical — `ok`;
- есть хотя бы одна сопоставимая готовая цена.

Текущий результат: `CANONICAL AUDIT`. Переключение заблокировано из-за отсутствия прямых WB/Ozon остатков, 28 пробелов политики, 115 решений `PENDING_ROP`, готовности 9,5% и паритета с legacy ниже порога.

## Следующие действия

1. Ответственный за цену закрывает оставшиеся значения маржи и MIN/MAX из отчёта пробелов.
2. Ответственный нажимает `Получить актуальные цены` либо ждёт плановый запуск каждые 20 минут. Сервер получает цены через API WB/Ozon, подставляет `articleKey` по алиасам и пересчитывает canonical; без свежего price snapshot не разблокируется ни одна строка.
3. После свежего снапшота команда проверяет расхождения цен, начиная с максимального абсолютного отклонения в shadow-отчёте.
4. После прохождения cutover-gate canonical включится автоматически; затем можно удалить дублирующий legacy-расчёт и оставить один ценовой движок.
5. Порог резкой цены уже хранится в серверной политике (10%); после стабилизации добавить SLA по задачам РОПа.
